# Discord 交互改造

## 2026-10-02 信息完整性复查

- 空的结束事件保留已接收的流式正文；结束事件只包含最后一条正文时，保留流中已有的前文。
- 分段保留空格、换行和缩进；流式预览的裁剪不作为最终正文。
- 扩展状态/widget 的预览保持简短，最终回复保留当前完整显示信息。
- 文本或续段发送失败时尝试完整 UTF-8 文本附件；附件也失败时仍明确报错，无法保证网络故障期间送达。
- 过长提问、选项和预填内容另发完整附件；超过 4000 字符的预填内容不再打开会静默截短的表单，提示通过聊天回答。
- 模型报告输出长度限制时明确提示回复可能未完成。

构建及 19 个测试套件通过，包括空结束事件、完整 widget、空白保留和附件内容一致性回归。尚未在真实 Discord 服务器验证，也未部署本地修改。

本次参照 [Hermes 的 Discord adapter](https://github.com/NousResearch/hermes-agent/blob/main/plugins/platforms/discord/adapter.py) 的成品交互方式，重做网关的文字聊天与操作流程。参考读取日期为 2026-09-30，重点是处理中/结束表情、原消息预览更新、结束后才发送溢出分段，以及提问和命令的收尾。

## 现在的行为

| 场景 | Discord 表现 |
| --- | --- |
| 收到任务 | 回复原用户消息，添加 👀，显示思考状态与已用时间 |
| 模型回复/工具执行 | 同一条回复显示文字预览与当前活动，更新合并并按顺序发送 |
| 等待确认或输入 | 回复显示“等待你的回答”；单独的提问提供按钮或填写弹窗 |
| 回答提问 | 原提问显示已选择/已提交并清除按钮；回复在原消息继续更新 |
| 提问超时/取消 | 原提问标记原因并清除按钮，RPC 收到取消回应，任务可继续收尾 |
| 完成 | 原回复替换为完整内容并移除停止按钮；👀 换为 ✅ |
| 失败 | 保留已生成的文字，显示错误；👀 换为 ❌ |
| 停止 | 使用停止按钮或 `/stop`；保留已有文字与会话，收尾显示 🛑 |
| 超长回复 | 生成期间只编辑预览；最终分段发送完整内容，保持代码围栏与语言 |
| 部分分段发送失败 | 明示已发送段数与失败情况，避免重新发送已有前缀 |
| slash 命令 | 更新 Discord 已延迟的原响应，消除一直“思考中”的状态 |
| 模型/历史会话选择 | 操作结果更新回原选择器；旧列表保持自己的会话快照 |

默认会话对应频道自己的持久化 Pi 文件，网关重启后仍可恢复。`/new` 建立新历史，`/detach` 返回该频道的默认历史，`/continue`、`/resume` 的明确绑定仍优先。当前网关使用一个共享 Pi RPC worker：忙碌时，其他频道或其他用户收到忙碌提示；只有原频道的任务发起者可以补充要求。停止按钮属于任务发起者，管理员也可使用 `/stop` 停止任务。

输入回答不会被复制到提问的完成标记中。消息不会自动触发 `@everyone`、角色或回复通知。表情更新失败不会阻止正常回复；可以通过 `platforms.discord.reactions: false` 关闭表情。

## 修复的生命周期问题

- 等待最终结果的记录先于 RPC 写入建立，避免快速完成的结果被错当作孤立事件。
- 回复结束前等待正在发送的编辑完成，后续旧预览无法覆盖最终答案。
- 流式预览不发送溢出段；最终更新复用已发送的分段，避免重复。
- 提问在发起 REST 请求前登记，因此发送期间的停止/超时也能解除 Pi 等待。
- 按请求、频道、消息和用户验证按钮；陌生或过期请求不会回落到另一个待回答问题。
- RPC 子进程退出、模型失败、网关停止都会结清等待者与计时器；旧子进程的延迟退出不会清掉新 worker。

## 验证

运行 `npm run build` 和 `npm test`。新增三个测试套件：

- `chat-reply.test.ts`：阻塞中的编辑、最终答案顺序、状态切换、停止/错误、编辑失败恢复、部分发送失败。
- `discord-experience.test.ts`：超长预览、slash 原响应、模型结果收尾、权限按钮、输入弹窗、超时、发送期间取消、停止按钮、会话列表归属、代码围栏、emoji 与频道 mention。
- `chat-runtime.test.ts`：真实网关回调与 RPC 行解析；模拟快完成、忙碌引导、跨用户/频道拦截、准备期间停止、模型错误和进程退出，并检查不同频道的独立 session 路径。

测试中的 Discord REST 与 RPC 模型输出使用替身。上线后仍需在自己的 Discord 测试频道确认真实 Bot 权限、slash 命令刷新与网络行为。这一轮改造覆盖文字聊天及命令交互；附件、语音和多 worker 并行处理不在本次范围内。

另外使用本机安装的 Pi 执行了真实 RPC 会话切换检查：频道 A → B → A 的 session 文件与 ID 均正确恢复；该检查不发起模型请求。
